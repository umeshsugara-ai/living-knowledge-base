## Scope
One append-only ledger (`docs/FEATURES.jsonl`) recording feature lifecycle events with reasoning,
one **generated** (never hand-edited) snapshot document (`docs/SNAPSHOT.md`, ≤200 lines, CI-checked
for staleness), a session-start hook extension surfacing recent removed/updated features (the
anti-cyclic guard at feature level — the decision-level guard already exists via
`lab-session-start.ps1`'s DECISION INDEX), and one memory pointer so Claude's own memory says "read
SNAPSHOT.md first."

## Criteria (each machine-checkable)

1. **`docs/FEATURES.jsonl` schema exists** (`schema/features_event.schema.json`, validated by the
   existing `schema/validate.py` harness — extend it, don't fork a second validator): one JSON
   object per line, required fields `{id, feature, event, date, unit, reason, links}`, `event ∈
   {planned, shipped, updated, removed}`; `reason` required and non-empty when `event ∈ {updated,
   removed}` (nullable/omittable only for `planned`/`shipped`).
2. **`scripts/features-ledger.mjs` exports `appendEvent(entry)`** — append-only (never rewrites
   prior lines), validates against the schema before writing, refuses (throws) on a missing
   `reason` for `updated`/`removed`. A CLI form `node scripts/features-ledger.mjs add <json-file>`
   for maker/checker use in later units.
3. **`scripts/snapshot.mjs` generates `docs/SNAPSHOT.md`** from, in order: (a) ARCHITECTURE §1
   verbatim; (b) a directory tree (depth 2 under repo root, excluding gitignored/node_modules/dist)
   with each top-level dir's one-line purpose pulled from its `package.json` `"description"` field
   or, absent that, the `| Path | Owns |` table in ARCHITECTURE §4; (c) a schema summary table
   auto-derived from `schema/*.schema.json` — collection name, required fields, whether it carries
   an `evidence`/provenance field; (d) the last 20 rows of `docs/FEATURES.jsonl` rendered as a
   table (date, feature, event, reason) with a note "full history: docs/FEATURES.jsonl"; (e)
   ARCHITECTURE §6 open questions verbatim. Output header states `<!-- GENERATED by
   scripts/snapshot.mjs — DO NOT EDIT. Edit the sources listed in this file's own header instead.
   -->`.
3b. **A hand-edit is caught, not silently overwritten.** If `docs/SNAPSHOT.md` exists and its
   content differs from what a byte-for-byte regeneration would produce AND git shows it was
   modified outside of a `snapshot.mjs` run (i.e. `node scripts/snapshot.mjs --check` was not run
   immediately before the diff), `--check` reports which lines diverged rather than just failing —
   proving drift is detectable, not just blockable.
4. **`docs/SNAPSHOT.md` ≤ 200 lines** (`wc -l`), enforced by adding a `snapshot` check into
   `pnpm lint:structure` (extends T-017's chain, does not fork a second lint entry point) — fails
   if the committed file differs from a fresh `node scripts/snapshot.mjs --check` run.
5. **Session-start hook extension:** `.claude/hooks/mc-sessionstart.ps1` (or a new small script it
   calls) prints, when `docs/FEATURES.jsonl` has any `removed`/`updated` row from the last 30 days,
   one line per such row: `FEATURE CHANGED: <feature> <event> on <date> — <reason>`. This is the
   feature-level anti-cyclic guard (mirrors the existing decision-level DECISION INDEX in
   `lab-session-start.ps1`). Hand-run proof in the manifest (simulate stdin, show the output line).
6. **Regeneration wired to the existing lifecycle points**, not a new standalone step: (a)
   `SessionEnd` — extend `lab-session-end.ps1` (or add a sibling hook) to run `node
   scripts/snapshot.mjs` if `docs/FEATURES.jsonl` changed this session; (b) `pnpm lint:structure`
   fails if `docs/SNAPSHOT.md` is stale (criterion 4) — that failure is itself the "regenerate
   before you can ship" gate, no separate `/landplane` dependency required for T-017b to pass.
7. **Memory pointer:** one memory file written under
   `C:\Users\Lenovo\.claude\projects\d--KnowledgeBase\memory\` (type: `project`) stating "read
   `docs/SNAPSHOT.md` first for this project; it is generated — never edit it directly, edit
   `ARCHITECTURE.md`/`schema/`/`docs/FEATURES.jsonl` instead", plus the corresponding one-line
   pointer added to `MEMORY.md`. Manifest shows both file contents.
8. **Tests exist and pass:** `node --test scripts/snapshot.test.mjs` (or folded into
   `scripts/lint.test.mjs`) covering: (a) `appendEvent` rejects a `removed` event with no `reason`;
   (b) `appendEvent` is append-only (two calls produce two lines, first line byte-identical after
   the second call); (c) `snapshot.mjs --check` exits 0 on a freshly generated file and non-zero
   after a hand-edit; (d) the generated file is ≤ 200 lines for the current repo state.
9. **Seed data, not vacuous:** `docs/FEATURES.jsonl` is seeded with `shipped` events for T-001,
   T-004, T-005 (v1), T-016, T-017 (pulling date + unit + a one-line reason from their already-
   committed `qa/manifests/`/verdict files — no invented data) so the ledger and generated snapshot
   are non-empty on first check.
